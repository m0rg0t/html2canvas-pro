# Box-shadow correctness tests

Run `node scripts/box-shadow-regressions.mjs` after building. These are independent native-DOM comparisons, not snapshots generated by html2canvas-pro itself.

## Running

```sh
pnpm install --frozen-lockfile
pnpm build
pnpm exec playwright install --with-deps chromium firefox webkit
node scripts/box-shadow-regressions.mjs
```

To run one engine:

```sh
BOX_SHADOW_BROWSERS=chromium node scripts/box-shadow-regressions.mjs
```

`BOX_SHADOW_OUTPUT` overrides the output directory. `BOX_SHADOW_BUNDLE` selects an ESM build relative to the repository root; the default is `dist/html2canvas-pro.esm.js`. Results from a different build must be identified separately.

## Coverage

There are 29 fixtures, each captured at device/capture scale 1 and 2, across Chromium, Firefox and Playwright WebKit: 174 combinations. Playwright WebKit on Linux is not Safari, genuine WKWebView, or a physical iOS device.

Coverage includes hard/blurred outer shadows, signed offsets, positive/negative spread, rounded/circular boxes, multiple-shadow order, inset shadows, mixed inset/outer shadows, transparent boxes/borders, currentColor, overflow clipping, layer opacity, blur/drop-shadow interactions, forced SVG filtering, and offset crops. A `none` fixture checks the shadow-free baseline.

## Reference and acceptance criteria

Each fixture is captured with its shadow and again with `box-shadow: none`, both in native DOM and through the library. The shadow-free controls expose unrelated fixture rendering errors.

Chromium and WebKit references use transparent native screenshots. The pinned Playwright Firefox runtime does not implement background omission. For Firefox, native screenshots are taken over white and black document backgrounds, and alpha is reconstructed using source-over compositing: black = RGB * alpha, white - black = 255 * (1 - alpha). These fixtures have no blend modes. Both original opaque screenshots are saved; no library pixels participate in reconstruction. A channel-consistency assertion checks the reconstruction assumptions.

Images are compared as premultiplied RGBA, ignoring RGB beneath zero alpha. The principal comparison uses the union of pixels affected by the native or rendered shadow, so empty margins cannot hide a missing or misplaced shadow.

Fixed limits, unchanged across engines and scales:

| Check | Limit |
| --- | --- |
| Shadow-free whole-image mean absolute error | 1.5 / 255 |
| Shadow-region mean absolute error | 8 / 255 |
| Shadow-region pixels with max channel error above 32 / 255 | At most 10% |
| Rendered/native shadow-effect energy ratio | 0.75 to 1.25 |

These are engineering tolerances, not a universal CSS conformance guarantee. Small blur/antialiasing differences are tolerated. Do not raise tolerances or approve a golden image merely to make an existing defect pass.

Each positive fixture also sends its shadow-free render through the same acceptance criteria and requires rejection. The runner continues after individual failures, writes all available evidence, and exits nonzero if anything fails. No current failures are suppressed or declared expected.

## Evidence and CI

The dedicated `Box-shadow correctness` workflow builds the checked-out source, runs browser jobs independently, and uploads artifacts even when tests fail. It does not publish a package.

Each artifact contains the built ESM bundle, the test script, and `tmp/box-shadow-regressions/` with:

- `index.html`: native/library/amplified-diff comparisons.
- `results.json`: revision, bundle SHA256, browser versions, platform, computed CSS, thresholds, metrics, and failures.
- Native, actual, difference and shadow-free PNGs; Firefox also retains native white/black references.

Download and extract an artifact, then open its HTML report. Distinguish setup/harness exceptions from completed pixel comparisons. In particular, an earlier run's Firefox `Not implemented` screenshot exception is not evidence of a library rendering bug.

The suite was introduced on a branch starting from v2.4.4 (`04842780655d91a21a424f2e9d03fb88ffd90a9f`) without changing production rendering code. It is intentionally capable of exposing defects already present in that release.
